# News Scraper

Асинхронный скрапер новостей о политике, рынках, ключевых ставках.
Страны: США, Россия, Китай.

## Стек

- Python 3.12
- Scrapy + scrapy-playwright — скрапинг
- FastAPI + Pydantic — API
- SQLite (aiosqlite) — хранилище
- **LangChain / LangGraph** — оркестрация агентов (только в `agents/`)
- **Langfuse (self-hosted)** — наблюдаемость
- **Ollama** — локальный инференс LLM (qwen2.5-coder)

## Архитектура (MVP, делаем по шагам)

Проект следует принципу **изоляции доменной логики от фреймворков**:

- `domain/` — чистая бизнес-логика (Scrapy, NLP, Pydantic-модели).
  НЕ зависит от LangChain, Ollama SDK и любых внешних фреймворков.
- `agents/` — слой оркестрации агентов. Здесь живёт LangChain/LangGraph.
- `infra/` — инфраструктурные адаптеры (клиенты Ollama, Langfuse, БД).
- `api/` — FastAPI-слой. Знает только о `domain/` и `agents/`.

### Почему так

1. **Устойчивость к санкциям и вендор-локу.** LangChain изолирован в `agents/`.
   Если завтра появится лучший фреймворк — переписываем один пакет, а не весь проект.
2. **Тестируемость.** `domain/` можно тестировать без LLM и без сети.
3. **Понятность.** Новый разработчик видит, где логика, где оркестрация, где инфраструктура.

## Принципы разработки

### Что можно
- Локальные модели через Ollama (никаких облачных LLM API).
- Self-hosted инструменты наблюдаемости (Langfuse, Phoenix).
- Open-source библиотеки с MIT/Apache-лицензиями.

### Что нельзя
- Облачные LLM API (OpenAI, Anthropic, Google) — санкционные риски.
- LangSmith и другие облачные SaaS для наблюдаемости — риск утечки данных.
- Прямые импорты LangChain в `domain/`, `api/`, `infra/`.

### Зависимости
- Версии фиксируются в `requirements.txt` с точностью до патча.
- При обновлении — прогон полного набора тестов.

### Шаг 1: Скрапер
- Scrapy-проект, асинхронные пауки
- Сбор: заголовок, URL, дата, источник, текст
- Сохранение сырых новостей в SQLite

### Шаг 2: NLP-обработка
- Sentiment: положительная / нейтральная / отрицательная
- Суммаризация: краткая суть новости
- Реализация через локальный Ollama (qwen2.5)

### Шаг 3: REST API
- FastAPI-сервис поверх SQLite
- GET /news — список новостей с фильтрами
- GET /news/{id} — детали
- GET /stats — агрегаты по sentiment и странам

### Шаг 4 (позже): UI
- Простой веб-интерфейс на FastAPI + Jinja2

## Стиль
- Type hints обязательны
- Async/await везде, где есть I/O
- Pydantic-модели для API и данных
- CSS-селекторы, не XPath

## Что НЕ делать
- Не использовать синхронные HTTP-запросы
- Не создавать файлы вне описанной структуры
- Не читать .venv/, __pycache__/, .git/
