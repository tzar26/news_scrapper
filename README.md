# News Scraper & AI Market Analyst

Асинхронный скрапер новостей и аналитическая система на базе локальных LLM для прогнозирования рыночных сигналов.
Проект собирает данные по трем странам (РФ, США, КНР), извлекает структурированные сигналы и позволяет задавать вопросы по базе данных через RAG и LangGraph-агента.

## Ключевые особенности

- **100% локальный инференс**: Никаких облачных API (OpenAI, Anthropic). Все модели (Qwen 2.5, BGE-M3) работают на собственном железе через Ollama (устойчивость к санкциям).
- **Hybrid Search**: Поиск по базе сочетает векторный поиск (pgvector) и полнотекстовый BM25 (PostgreSQL tsvector) с объединением результатов через RRF (Reciprocal Rank Fusion).
- **RAG с цитированием**: Ответы на вопросы опираются только на собранные статьи, с обязательными ссылками на источники.
- **LLM-категоризация**: Автоматическое определение темы статьи (Политика, Экономика, Энергетика и т.д.) с помощью локальной LLM (Qwen 2.5).
- **Агентная аналитика**: LangGraph-агент умеет не только искать статьи, но и отвечать на аналитические вопросы (например, «Сколько статей про энергетику мы собрали за 3 дня?») с помощью инструмента `get_metrics`.
- **Multi-step Agent (LangGraph)**: Агент умеет рассуждать, самостоятельно вызывать инструменты (поиск по базе) и сравнивать факты.
- **Observability**: Полный трейсинг всех шагов LLM (LangGraph, RAG, tool calls) через self-hosted Langfuse.
- **Streaming (SSE)**: Ответы печатаются в реальном времени в UI, агент показывает статусы своей работы («Ищу...», «Анализирую...»).
- **Архитектурная дисциплина**: Изоляция доменной логики от фреймворков (LangChain используется только в слое агентов), документирование всех решений через ADR.
- **NER**: Извлечение компаний, персон и стран с помощью LLM. Агент умеет искать по сущностям (например, «новости про ЦБ»).
- **Анализ новостного фона**: Агент умеет оценивать рыночный фон (Market Impact) по секторам, выделяя важные события (High/Medium) и их направление (Bullish/Bearish).
- **ML-сигналы**: Генерация торговых сигналов (BUY/SELL/NEUTRAL) на основе новостного фона и рыночных данных с Explainable AI.

## Технологический стек

- **Backend**: Python 3.12, FastAPI, Pydantic v2, SQLAlchemy 2.0 (async), asyncpg
- **База данных**: PostgreSQL 17 + pgvector (векторы + реляционные данные), Redis (кэш, брокер Celery)
- **LLM & AI**: Ollama (Qwen2.5-Coder 14B для генерации, BGE-M3 для эмбеддингов), LangGraph (оркестрация агента), Scikit-learn (RandomForest), Plotly
- **Data Pipeline**: Celery + Celery Beat (фоновый сбор), feedparser, httpx
- **Frontend**: Streamlit (интерактивный дашборд)
- **Observability**: Langfuse (self-hosted)
- **Инфраструктура**: Docker Compose, GitHub Actions (CI)

## 📈 ML & Trading Signals (Private Phase)

Публичный MVP показывает сбор, RAG и агента. В приватной ветке (`private/trading`) реализован слой **предиктивной аналитики**. В публичном репозитории представлены архитектурные решения (без кода).

### Pipeline
1. **Entity Linking**: Привязка новостей к тикерам Мосбиржи (SBER, GAZP и т.д.) через словарь синонимов и NER.
2. **Feature Engineering**:
   - `market_pressure` (сумма влияния новостей: bullish +1, bearish -1).
   - `news_count` (количество новостей за день).
   - `vol_5d`, `vol_20d` (волатильность).
   - `adv_20d` (средний объём торгов).
   - `volume_ratio` (аномалии объёма).
3. **ML-модель**: RandomForest (с калибровкой Platt scaling) предсказывает вероятность роста (`P(up)`) на следующий день.
4. **Walk-Forward Validation**: Честная оценка на скользящем окне (без look-ahead bias).

### Feature Importance (анализ фич)

Мы провели анализ важности фич (Feature Importance) для RandomForest, чтобы понять, что влияет на предсказание. На текущем объёме данных (104 записи с новостями) результаты следующие:

| Фича | Важность |
|------|----------|
| `vol_20d` (волатильность за 20 дней) | 0.24 |
| `vol_5d` (волатильность за 5 дней) | 0.24 |
| `adv_20d` (средний объём торгов) | 0.23 |
| `sector_pressure` (средний market_pressure по сектору) | 0.135 |
| `news_count` (количество новостей) | 0.12 |
| `market_pressure` (сумма влияния новостей) | 0.09 |
| `has_summary` (флаг суммаризации) | 0.08 |

**Интерпретация:** На малых данных волатильность и объём доминируют над новостным фоном. Это ожидаемо: модель пока не видела достаточно примеров, где `market_pressure` сильно менялся. В следующей итерации (при 200+ записях) мы добавим фичи доминирования (`bullish_count`, `dominance`), чтобы усилить сигнал от новостей (ADR-024).

### Версионирование моделей

Каждая обученная модель сохраняется с версией и метаданными (дата, Accuracy, важность фич). Это позволяет:
- Отслеживать прогресс (например, Accuracy v1.0 = 0.57, v1.1 = 0.62).
- Честно оценивать Track Record (ретроспективу), группируя сигналы по версии модели.

Пример: `models/signal_model_v20261110_1150.pkl` + `signal_model_v20261110_1150.json`.

### Entity Salience (ADR-027)

Мы внедрили механизм выделения «главного героя» новости (Entity Salience), чтобы система не путала субъект и объект действия. Например, в новости «Клиенты ВТБ покупают акции VK» сигнал должен генерироваться для VK, а не для ВТБ.

**Результат внедрения:**
- Механизм корректно обрабатывает граничные кейсы (брокерские платформы, обзоры, смешанные новости).
- Датасет пересобран: 113 записей с новостями (было 104).
- **Честное ограничение:** Accuracy снизилась с 0.57 до 0.52. Это ожидаемо: мы убрали «шум» (новости, привязанные ко всем тикерам), и модель стала учиться на более чистых, но и более сложных данных. Плюс на 113 записях высокая нестационарность (std=0.34 по окнам Walk-Forward). Мы вернёмся к оценке при 200+ записях (ADR-024).

### API & UI
- **`GET /signal/{ticker}`**: Возвращает торговый сигнал (BUY/SELL/NEUTRAL), уверенность и **доказательства** (список новостей, повлиявших на решение).
- **`GET /candles/{ticker}`**: Исторические свечи для графиков.
- **Streamlit страница Signals**: Терминал трейдера с графиками Plotly (Candlestick), прогресс-барами уверенности и раскрывающимися новостями.

### Explainable AI (XAI)
Мы не просто выдаём сигнал, мы показываем **почему** модель так решила. Каждая карточка сигнала содержит:
- Список новостей с ссылками.
- Дату и направление влияния (`bullish`/`bearish`).
- Уверенность в процентах.

## Как запустить локально

### Предварительные требования
- Python 3.12
- Docker и Docker Compose
- Запущенный сервер Ollama (локально или удаленно) с моделями `qwen2.5-coder:14b-16k` и `bge-m3`.

### 1. Клонирование и установка
```bash
git clone https://github.com/your-username/news_scruper.git
cd news_scruper
python3.12 -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"
```

### 2. Настройка окружения
Создайте .env файл на основе .env.example:

```bash env
DATABASE_URL=postgresql+asyncpg://news:news@localhost:5434/pet_news
REDIS_URL=redis://localhost:6379/0
OLLAMA_BASE_URL=http://localhost:11434 # или ваш IP
LANGFUSE_PUBLIC_KEY=pk-lf-...
LANGFUSE_SECRET_KEY=sk-lf-...
LANGFUSE_HOST=http://localhost:3000
PIPELINE_START_DATE=2026-08-01
```

### 3. Запуск инфраструктуры
Запускает PostgreSQL (с pgvector) и Redis
```bash
docker compose up -d postgres redis
```

Можно запустить всё в контейнере и использовать (пропускаем 4-6)
```bash
docker compose up -d
```
Останов в случае контейнерного запуска
```bash
docker compose down
```

### 4. Миграции БД
```bash
alembic upgrade head
```

### 5. Скачивание моделей (если Ollama локально)
```bash
ollama pull qwen2.5-coder:14b-16k
ollama pull bge-m3
```

### 6. Запуск
```bash
# Терминал 1: API
uvicorn news_scraper.api.main:app --reload --port 8000

# Терминал 2: Streamlit Dashboard
streamlit run src/news_scraper/dashboard/app.py

# Терминал 3: Celery Worker (для фонового сбора и эмбеддингов)
celery -A news_scraper.tasks.celery_app:celery_app worker --loglevel=info
```

### Доступ к интерфейсам

Streamlit Dashboard: http://localhost:8501

FastAPI Swagger UI: http://localhost:8000/docs

Langfuse UI: http://localhost:3000 (если запущен)

## Текущий статус и метрики

На данный момент собрано **~37000 статей** из **24 источников**. База данных включает векторные представления (BGE-M3, 1024d) и HNSW-индекс для быстрого поиска.

- **Категоризация**: 100% статей классифицированы LLM (в фоне).
- **Retrieval (Hybrid search)**: `Recall@5` ~ 0.53, `Precision@5` ~ 0.73, `MRR@5` ~ 0.90.
- **Агент**: Поддерживает tool calling (поиск и агрегация метрик), трейсинг через Langfuse.
- **ML-модель**: Средняя Accuracy **0.57** (медиана 0.57) на 104 записях с новостями (Walk-Forward Validation: 10 окон, 70 тестовых примеров). В очереди ещё ~45 000 статей для накопления базы. Анализ важности фич показал доминирование волатильности (`vol_20d`, `vol_5d`) над новостным фоном (`market_pressure`) на текущем объёме данных.
