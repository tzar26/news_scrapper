# ADR-009: Hybrid search — BM25 + vector через RRF

Дата: 2026-10-13
Статус: принято

## Контекст

Эмпирика из ADR-008 показала потолок чистого vector search:
- «ключевая ставка ЦБ» → 1/5 релевантных
- «автопром Китая» → 1/5
- «золото» → 1/5
- «нефть ОПЕК» → 5/5

Причины разные: общие термины, омонимия, составные запросы.
Чистый vector не различает точные термины и семантику слов.

## Решение

Hybrid search: **BM25 через PostgreSQL tsvector + vector через pgvector**,
объединение через **RRF (Reciprocal Rank Fusion)**.

### 1. BM25 через функциональные индексы

Не добавляем `tsv`-столбцы в схему. Используем **функциональные GIN-индексы**:

```sql
CREATE INDEX ix_articles_tsv_ru ON articles
USING gin (to_tsvector('russian', title || ' ' || text));

CREATE INDEX ix_articles_tsv_en ON articles
USING gin (to_tsvector('english', title || ' ' || text));

## Эмпирические результаты (2026-10-13)

Hybrid search на 1191 статье, top-5:

- «ключевая ставка ЦБ»: статья 1372 стала явным лидером
  (RRF 0.033 vs 0.016 у остальных). Hybrid сработал — она
  в топе у обоих методов.
- «нефть ОПЕК»: 5/5, без изменений (данные позволяют).
- «автопром Китая»: появились новые статьи («Автостат»,
  «Автоваз») — recall от BM25. Качество всё ещё ограничено
  данными, но прогресс есть.
- «золото»: статья 448 (металл) осталась лидером, но
  фигурист Дикиджи поднялся до 0.032. **Омонимия: BM25
  находит точное слово, не различает смысл.**

**Выводы:**
1. RRF работает — усиливает статьи, релевантные обоим методам.
2. Эффект слабый из-за однородности базы и малого объёма.
3. Омонимия — фундаментальное ограничение. Решение:
   reranking (cross-encoder) или больше данных.

**Следующие шаги:**
1. Расширение источников (отраслевые китайские, финансовые).
2. Reranking — при плохом precision на больших базах.

## Диагностика: vector vs BM25 раздельно (2026-10-13)

Ключевые наблюдения на 1191 статье:

**«ключевая ставка ЦБ»:**
- Vector: 5 результатов (широкий recall).
- BM25: 1 результат (только 1372, буквальное совпадение).
- RRF: 1372 получает вклад от обоих → явный лидер.

**«автопром Китая»:**
- Vector: 5 семантически близких (неточных).
- BM25: пусто (`plainto_tsquery` AND — нет статьи с обоими
  терминами).
- RRF: работает только с vector. Это корректно — BM25
  не должен находить «похожее».

**«золото»:**
- Vector: металл + фигурист + бриллианты + ВЦИОМ + ЦБ.
- BM25: металл + Мишустин (буквальное вхождение «золот» в текст) + фигурист.
- RRF: фигурист поднялся выше за счёт BM25.

**Интерпретация:**
- BM25 отвечает за precision, vector за recall.
- RRF складывает вклад обоих — работает как задумано.
- Омонимия («золото») — фундаментальное ограничение обоих
  методов. Решение: уточнение запроса пользователем или
  reranking.

**Решение по AND-логике BM25:** оставляем `plainto_tsquery` (AND).
Стратегия hybrid не требует от BM25 recall — vector его даёт.
