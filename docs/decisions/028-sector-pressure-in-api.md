# ADR-028: Интеграция Sector Pressure в API (Runtime vs Batch)

Дата: 2026-11-12
Статус: реализовано (Приватная ветка `private/trading`)

## Контекст

При генерации сигналов в реальном времени (`ml/signal.py`) мы изначально использовали заглушку для фичи `sector_pressure = 0.0`, так как её расчёт требовал дополнительного запроса к БД. Модель RandomForest, обученная на датасете с реальным `sector_pressure`, на инференсе «слепла» и выдавала преимущественно сигналы BUY (базовая вероятность), игнорируя секторный контекст.

## Решение

1. В `ArticleRepository` добавлен метод `get_sector_pressure(sector, days=3)`, который:
   - Находит все тикеры сектора через `_ticker_map`.
   - Запрашивает статьи за последние N дней.
   - Считает средний `market_pressure` по этим статьям.
2. В `ml/signal.py` перед формированием вектора фич (`X`) вызывается этот метод, и реальное значение `sector_pressure` подставляется в модель.

## Результат

Картина сигналов в дашборде изменилась кардинально:
- До: большинство тикеров получали BUY (из-за игнорирования сектора).
- После: энергетика (LKOH, NVTK) ушла в SELL (негативный фон в секторе), банки (SBER, VTBR) — в NEUTRAL (смешанный фон). Уверенность в сигналах SELL выросла до 72–79%.

## Последствия

- Модель теперь использует секторный контекст, что делает сигналы более реалистичными.
- Требуется мониторинг производительности метода `get_sector_pressure` (запрос к БД на каждый тикер).
- В будущем можно кешировать `sector_pressure` (например, в Redis) на 1 час, чтобы не делать лишних запросов.
