# ADR-011: Метрики оценки retrieval

Дата: 2026-10-15
Статус: принято

## Контекст

Все изменения retrieval (hybrid search, num_ctx, выбор моделей)
делались эмпирически, без числовых метрик. Для оценки reranking
и будущих оптимизаций нужен измеримый baseline.

## Решение

### Метрики

Только retrieval (не generation). Объективные, не требуют LLM-судьи:

- **Recall@k** — доля релевантных, попавших в top-k.
- **Precision@k** — доля релевантных среди top-k.
- **MRR@k** — 1 / (позиция первого релевантного), усреднённая по запросам.

### Test set

`tests/rag/queries.yaml` — 12 запросов, покрывающих темы проекта:
ключевая ставка, нефть, автопром Китая, золото, инфляция, акции США,
экспорт газа, экономика Китая, санкции, ФРС, бюджет, облигации.

### Разметка

Pooling-подход (стандартный в IR):
- Для каждого запроса retrieval возвращает top-20.
- Размечаем вручную: релевантно / нерелевантно (бинарно).
- «Сомнительные» → false (строгая разметка).
- Релевантные, выпавшие из top-N при следующем прогоне, сохраняются
  в датасете с `source: previous_annotation` — чтобы recall корректно
  учитывал «промахи».

### Скрипты

- `scripts/dump_candidates.py` — обновляет candidates.yaml с переносом
  старой разметки по ID.
- `scripts/eval_retrieval.py` — считает метрики, сохраняет baseline.
- `tests/rag/baselines/` — история baseline для сравнения прогонов.

## Baseline

### v0.13 (до расширения корпуса, 901 статья)

    recall@5     0.5595
    precision@5  0.6364
    mrr@5        0.9091

### v0.14 (после +700 статей, ~1700 статей)

    recall@5     0.5388
    precision@5  0.8000   (+0.16)
    mrr@5        1.0000   (+0.09)

### v0.15 (после +620 статей, 2320 статей)

    recall@5     0.5286
    precision@5  0.7333
    mrr@5        0.8958

**Изменения:**
- Добавлен активный запрос «ФРС ставка» (был no relevant).
  Единственная релевантная статья на позиции #4 → mrr упал.
- Разметка новых id проводилась строже.
- Расширение корпуса (620 статей) вытеснило часть точных
  попаданий из top-5.

**Тренд recall@5 по версиям:**
- v0.13 (901): 0.5595
- v0.14 (1700): 0.5388
- v0.15 (2320): 0.5286

Recall медленно снижается с ростом корпуса — классика IR.
Precision остаётся высокой (0.73 vs 0.64 в v0.13).

## Интерпретация

**Precision и MRR выросли** — найденное более релевантно и стоит
выше в списке. Hybrid search + расширение корпуса улучшили точность.

**Recall слегка упал** — в базе стало больше релевантных,
retriever находит столько же. Классический trade-off при
расширении корпуса: precision vs recall.

**Это не деградация**, а смена баланса. Дальше нужно улучшать recall.

## Слабые запросы (кандидаты на reranking)

| Запрос | recall@5 | Причина / гипотеза |
|---|---|---|
| нефть ОПЕК | 0.23 | AND-логика BM25 режет широкий запрос |
| бюджет России | 0.22 | Много релевантных выпало из top-20 |
| санкции против России | 0.25 | Retrieval не находит deep candidates |
| рынок акций США | 0.26 | Перегрузка темы, 6 выпало из top-20 |

**Гипотеза:** reranking (cross-encoder) поднимет релевантные статьи
из позиций 6–20 в top-5. Проверка — после реализации reranking.

## Ограничения методологии

- **Pooling** — мы не знаем всех релевантных, только те что попали
  в top-20. Это стандартно для IR, но даёт **приближение** recall.
- **12 запросов** — мало для статистики. Расширять по мере надобности.
- **Один annotator** — субъективность. В команде нужна хотя бы
  перекрёстная разметка 10% для оценки согласия.
- **Русский + английский смешаны** — метрики усредняют языки.

## Что НЕ делаем сейчас

- Generation-метрики (faithfulness, answer relevance) — сложнее,
  требуют LLM-судью. Отдельно и позже.
- Автоматизированные CI-проверки метрик — когда стабилизируется.
