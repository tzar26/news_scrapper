# ADR-026: Data Integrity — Ленивая проверка доступности новостей (Health Check)

Дата: 2026-11-10
Статус: план (Приватная ветка `private/trading`)

## Контекст

В процессе эксплуатации системы мы заметили, что новостные источники иногда удаляют или изменяют статьи после публикации. Если система сгенерировала сигнал на основе такой статьи, трейдер видит «доказательство», которое ведёт на 404. Это подрывает доверие к инструменту.

Массовая проверка всех 47 000+ статей (CrawlDB) — избыточна и дорога. Нам нужно решение, которое защищает именно те статьи, которые влияют на текущие торговые сигналы.

## Решение

Внедрить **«Ленивую» проверку (Lazy Health Check)** на уровне генерации сигнала.

### Логика
1. При вызове эндпоинта `GET /signal/{ticker}` система выбирает новости за последние 3 дня.
2. **Фильтр:** Проверяются только статьи с `impact = 'bullish'` или `'bearish'`.
   * *Почему:* Нейтральные статьи не влияют на `market_pressure` и не участвуют в формировании направленного сигнала. Если нейтральная статья удалена, это не искажает логику сигнала.
3. Для каждой отобранной статьи выполняется `HEAD`-запрос к URL (с таймаутом 2 секунды).
4. Если URL возвращает `404` (Not Found) или `410` (Gone):
   * Статья исключается из расчёта сигнала.
   * В базе помечается флаг `is_alive = False`.
5. Если URL доступен, статья участвует в расчёте как обычно.

### Ограничения
* Метод не защищает от «подмены» контента (когда URL жив, но текст другой). Для этого нужен более сложный механизм (сравнение `content_hash`), который отложен до следующей итерации.
* Проверка выполняется только для активных сигналов, поэтому не нагружает систему.

## Последствия

* Трейдер видит только те доказательства, которые реально существуют в сети.
* Мы избегаем «мусорных» сигналов на основе удалённых статей.
* Сложность реализации: **S** (небольшой патч в `ml/signal.py` и `ArticleRepository`).
