# Решение: базовый RSSSource и реестр источников

Дата: 2026-10-06
Статус: принято

## Контекст

Нужно собирать новости по 3 странам (РФ, США, КНР) из нескольких
источников на страну. У большинства — RSS. Полная реализация в каждом
файле (как в текущем KommersantSource) приводит к копипасте: httpx,
parse_rss, aclose идентичны.

Также нужно предусмотреть не-RSS источники (HTML, API, Playwright),
но реализовывать их сейчас преждевременно.

## Решение

### 1. Общая логика RSS — в базовом классе RSSSource

`scraper/sources/rss.py::RSSSource` содержит всё: init клиента,
fetch, aclose. Подклассы переопределяют только атрибуты:

    class NPRSource(RSSSource):
        name = 'npr'
        country = Country.USA
        rss_url = 'https://feeds.npr.org/1001/rss.xml'

### 2. Источник = тонкий подкласс, файл на источник

Оставляем паттерн «один файл = один источник». Это позволяет:
- легко добавлять (5 строк),
- изолировать специфику при необходимости (override метода),
- AI-помощники хорошо генерируют по образцу.

### 3. Реестр источников

`sources/registry.py` содержит:
- `ALL_SOURCES: list[type[Source]]` — список всех реализованных.
- `get_sources_by_country(country) -> list[type[Source]]` — фильтр.

### 4. Не-RSS источники: тот же Protocol, свои парсеры

HTML, JSON API, Playwright — реализуют `Source`, но со своим парсером
в `scraper/parsers/`. Добавляются по мере необходимости, не сейчас.

## Альтернативы

1. **Один файл = один источник с полной реализацией.** Отвергнуто:
   копипаста 15 строк × N источников, расхождения при правках.
2. **Dataclass-конфиг вместо наследования.** Отвергнуто: менее
   привычно, специфику источника (кастомный маппинг) некуда положить
   кроме condition-ов в общем коде.
3. **Автодискавери через pkgutil.** Отвергнуто: YAGNI, отладка хуже,
   явный список читается лучше.

## Последствия

- Новый RSS источник = 1 файл, 5 строк.
- Специфику добавляем через override метода, а не через условную логику.
- `registry.py` — единая точка правды: где что собирается.
- Для не-RSS источников паттерн тот же, но со своим парсером.
