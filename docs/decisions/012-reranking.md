# ADR-012: Reranking — опциональная фича для /ask

Дата: 2026-10-16
Статус: принято

## Контекст

Baseline retrieval (hybrid: BM25 + vector + RRF) показал:
- v0.13 (901 статья): recall@5 = 0.5595
- v0.14 (1700): recall@5 = 0.5388
- v0.15 (2320): recall@5 = 0.5286

Слабые запросы: «нефть ОПЕК» (recall 0.22), «бюджет России» (0.18),
«санкции против России» (0.22). Гипотеза: cross-encoder поднимет
релевантные из позиций 6–30 в топ-5.

## Что пробовали

### Попытка 1: FlashRank + ms-marco-MultiBERT-L-12

**Результат:** катастрофическое падение метрик.
- recall@5: 0.54 → 0.21
- precision@5: 0.80 → 0.31

**Причина:** модель обучена на английском MS MARCO, мультиязычный
компонент слабый. На русских текстах работает как «мешок слов».

### Попытка 2: sentence-transformers + jina-reranker-v2-base-multilingual

Модель 278M, 557 МБ, работает на GPU (GTX 1650).

**Замеры на v0.14 (1700 статей):**

| Метрика | Hybrid | Reranked | Δ |
|---|---|---|---|
| recall@1 | 0.1586 | 0.1817 | +0.023 |
| recall@3 | 0.4303 | 0.3830 | -0.047 |
| recall@5 | 0.5388 | 0.5463 | +0.008 |
| precision@1 | 1.0000 | 1.0000 | 0 |
| precision@3 | 0.9697 | 0.8182 | -0.152 |
| precision@5 | 0.8000 | 0.7273 | -0.073 |
| mrr@5 | 1.0000 | 1.0000 | 0 |

**Замеры на v0.15 (2320 статей):**

| Метрика | Hybrid | Reranked | Δ |
|---|---|---|---|
| mrr@1 | 0.8333 | 0.9167 | +0.083 |
| mrr@3 | 0.8750 | 0.9167 | +0.042 |
| mrr@5 | 0.8958 | 0.9167 | +0.021 |
| precision@1 | 0.8333 | 0.9167 | +0.083 |
| precision@3 | 0.8333 | 0.7778 | -0.056 |
| precision@5 | 0.7333 | 0.6833 | -0.050 |
| recall@1 | 0.1299 | 0.1502 | +0.020 |
| recall@3 | 0.3468 | 0.3263 | -0.021 |
| recall@5 | 0.5286 | 0.4785 | -0.050 |

## Вывод

**Reranker делает стабильно одно и то же** (эффект воспроизводится
на двух корпусах):

- **Улучшает top-1**: mrr@1, precision@1, recall@1 растут.
- **Ухудшает top-3-5**: precision@3-5, recall@5 падают.

**Интерпретация:** cross-encoder уверенно ставит самую релевантную
статью на #1, но вытесняет из top-5 те, что hybrid попадал
«по совокупности сигналов».

## Решение

**Reranker — опциональная фича для `/ask`.**

- **`/search`** — только hybrid. Пользователь видит top-5,
  важнее общая релевантность.
- **`/ask`** — гибрид по умолчанию, флаг `rerank: bool = False`
  включает cross-encoder.
- **По умолчанию не включаем** — не измерено влияние на generation,
  латентность растёт (+1-2 сек).

**Почему не отказались полностью:**
- Top-1 становится точнее — для LLM это может быть важно.
- Эффект на больших корпусах может измениться.
- Гибкость — пользователь может выбрать.

## Что проверить в будущем

- Generation-метрики (faithfulness, answer relevance) с/без
  reranker. Если с reranker ответы точнее — включить по умолчанию.
- На 10k+ статьях поведение может измениться — вернуться к замеру.

## Что сохраняем в репозитории

- `src/news_scraper/rag/reranker.py` — код готов.
- `scripts/eval_retrieval_reranked.py` — воспроизводимая оценка.
- `scripts/test_reranker.py` — визуальная проверка.
- Зависимости: `sentence-transformers>=6.0`, `transformers>=4.40,<5`.

## Ограничения методологии

- Test set 12 запросов — статистика слабая.
- Один annotator.
- Замеры на русско-английском смешанном корпусе.
- Generation-качество не измерялось.

## Финальный ретест на 22 000 статей (2026-10-30)

Мы провели ретест Jina Reranker v2 на расширенном корпусе (22 388 статей).

| Метрика | Baseline (Hybrid) | Reranked (22k) | Δ |
|---|---|---|---|
| recall@5 | 0.5286 | 0.3884 | -0.14 |
| precision@5 | 0.7333 | 0.3636 | -0.37 |
| mrr@5 | 0.8958 | 0.5530 | -0.34 |

**Вердикт:** Reranker катастрофически ухудшает метрики на большом корпусе.
Причина: модель (278M) не справляется с шумом 22k документов и теряет контекст, который ловит Hybrid Search (RRF).

**Решение:** Reranker окончательно исключён из пайплайна (флаг `rerank` удалён или оставлен только для экспериментов). Hybrid Search (BM25 + Vector + RRF) признан оптимальным решением.
