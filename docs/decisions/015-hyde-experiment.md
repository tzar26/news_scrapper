# ADR-015: HyDE — проверено, не даёт улучшения на текущем стеке

Дата: 2026-10-26
Статус: принято, отложено

## Контекст

Baseline retrieval (hybrid search) показал:
- recall@5 = 0.5286
- precision@5 = 0.7333

Гипотеза: HyDE (генерация гипотетического ответа перед эмбеддингом) может улучшить recall на запросах, где пользователь использует другие слова.

## Эксперимент

Реализован `rag/hyde.py`. Функция `generate_hypothetical_answer()` генерирует 2-3 предложения через Qwen 2.5 14B, затем эмбеддинг этого текста используется для поиска.

## Результат

| Метрика | Baseline | HyDE | Δ |
|---|---|---|---|
| recall@5 | 0.5286 | 0.3597 | -0.17 |
| precision@5 | 0.7333 | 0.2667 | -0.47 |
| mrr@5 | 0.8958 | 0.5208 | -0.38 |

**Все метрики значительно упали.**

## Почему HyDE не сработал

1. **Qwen 14B слаба для HyDE.** Модель генерирует общие фразы, которые уводят поиск от конкретных статей.
2. **Длинный гипотетический текст** ищет «рассуждения аналитика», а не реальные новости.
3. **Потеря точных терминов** (ОПЕК, Brent), которые BM25 так хорошо ловил.

## Решение

- **Не включаем HyDE по умолчанию** (флаг `use_hyde=False`).
- Код остаётся в репозитории для будущих экспериментов.
- Гипотеза для будущего: попробовать HyDE с моделью побольше (Qwen 32B или облачной) или с более коротким (1 предложение) гипотетическим документом.

## Вывод

**Отрицательный результат — тоже результат.** Мы сэкономили время и не стали внедрять метод, который ухудшает качество.
