# ADR-029: Кеширование торговых сигналов

Дата: 2026-11-12
Статус: план (Приватная ветка `private/trading`)

## Контекст

Генерация сигнала — ресурсоёмкая операция: запрос к БД, Health Check новостей (HEAD-запросы), расчёт `sector_pressure`, загрузка ML-модели. При частом обновлении дашборда (или переключении вкладок) это создаёт избыточную нагрузку на API и Ollama (если Health Check).

## Решение

Внедрить кеширование сигналов в Redis.

- **Ключ:** `signal:{ticker}`.
- **Ttl:** 1 час (настраиваемый параметр `SIGNAL_CACHE_TTL_SECONDS`).
- **Логика:** При запросе `GET /signal/{ticker}` API сначала проверяет Redis. Если сигнал есть и его возраст < TTL, возвращает его из кеша. Если нет — генерирует новый, сохраняет в Redis и возвращает.

## Последствия

- Нагрузка на API и БД снижается в разы (при повторных запросах).
- Сигналы становятся «снимком» на момент генерации (что правильно для ретроспективы).
- При необходимости можно сбросить кеш вручную (например, после переобучения модели).
