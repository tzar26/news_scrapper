# ADR-010: Стратегия работы с категориями статей

Дата: 2026-10-13
Статус: принято

## Контекст

В `articles.category` сейчас лежит **не raw-значение** из RSS,
а результат маппинга через `_CATEGORY_MAP` в `parse_rss`.

Примеры:
- RSS дал `'Новости'` → в `_CATEGORY_MAP` нет → `Category.OTHER`
- RSS дал `'politics'` → в `_CATEGORY_MAP` есть → `Category.POLITICS`
- RSS дал пусто → `default_category` → `Category.OTHER`

Проблема: **raw-значение теряется при парсинге**. Нельзя
отладить маппинг — не понять, почему 75%+ в `other`: потому
что фид не даёт категорию, или потому что `_CATEGORY_MAP`
её не знает.

В будущем (этап NLP-обогащения) планируется **LLM-классификация**.

## Решение

### 1. Добавить `category_raw` (миграция сейчас)

- Поле `category_raw: str | None`, nullable, без индекса.
- В `parse_rss` сохраняем **и** raw, **и** результат маппинга.
- Старые статьи: `category_raw = NULL` (не восстановить).
- Назначение: отладка маппинга, диагностика источников.

### 2. В будущем — `category_predicted`

- Поле `category_predicted: str | None`, nullable.
- Заполняется Celery-задачей enrichment через LLM.
- `category` (результат маппинга) остаётся как есть.
- Фильтры API: `COALESCE(category_predicted, category)`.

## Итоговая схема полей

- `category_raw` — что буквально прислал RSS. Отладка. Может быть NULL.
- `category` — результат маппинга raw. Текущая рабочая категория.
- `category_predicted` — LLM-классификация. Появится позже.

## Обоснование

**Почему не перезаписывать `category` при LLM-классификации:**
- Потеря исторической логики маппинга.
- При смене модели/промпта — не с чем сравнить.

**Почему `category_raw` нужен сейчас, а не потом:**
- Каждый день без него — потеря данных о том, что фиды присылают.
- Стоимость миграции минимальна.
- Отладка маппинга окупается на этапе расширения источников.

**Почему без индекса:**
- Не используется в фильтрах.
- Только для чтения при отладке.

## Альтернативы

1. **Перезаписывать `category` при LLM-классификации.**
   Отвергнуто: потеря исходных данных.
2. **Отдельная таблица `article_categories`.**
   Отвергнуто: оверинжиниринг на 2 поля.
3. **Восстановить raw из существующих данных через reverse mapping.**
   Отвергнуто: это гадание, не восстановление.

## Когда реализовать `category_predicted`

- При старте работы над LLM-классификацией.
- Когда анализ покажет, что `category='other'` мешает продукту.
